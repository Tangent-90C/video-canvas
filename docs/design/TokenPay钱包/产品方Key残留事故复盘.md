# 产品方 Key 残留事故复盘

> 日期：2026-11-18  
> 状态：已修复，生产迁移待发布  
> 影响范围：TokenPay 钱包后台配置、TokenDance 模型目录同步

## 1. 事故

管理后台的 TokenPay 钱包设置页仍保留「TokenDance API Key」输入项，并显示「产品方的 Key，只用来同步模型目录」。后端同步模型目录时也继续读取 `channel:tokenpay` 并向目录接口发送 Bearer。

这违反了明确的产品契约：TokenPay 钱包渠道只使用用户通过 OAuth 授权的 `wallet:<uid>`，后台不保存、不使用产品方 Key。

## 2. 影响

- 用户生成、Agent 对话和管理员试跑没有使用该产品方 Key，执行路径始终读取用户自己的钱包 Key。
- TokenDance 的模型目录是公开接口，该 Key 对同步没有必要，属于无业务用途的长期凭证残留。
- 设置页持续暗示可以用产品方 Key 承担调用，给后续实现留下错误入口。
- 数据库继续保存了一份本不该存在的产品方凭证。

## 3. 根因

我把“Key 只用于目录、不参与用户支付”当成了可接受方案，没有继续验证目录接口是否真的需要鉴权。需求已经从“限制用途”明确为“移除该 Key”，实现却停留在修改提示文案，没有删除输入项、存储路径和同步鉴权。

自动化测试也只覆盖了“钱包任务使用用户 Key”，没有覆盖“钱包渠道不得存在产品方 Key”和“目录同步不得携带产品方 Key”。文档同时把错误的目录鉴权方式写成了设计事实，进一步放大了问题。

## 4. 修复

- TokenPay 设置页删除「TokenDance API Key」输入项及保存逻辑。
- TokenPay 钱包渠道同步模型目录时不读取渠道 Key，不发送 `Authorization`。
- 后台接口禁止给钱包渠道设置产品方 API Key 或 Secret Key。
- 渠道健康和模型状态计算识别钱包渠道：没有产品方 Key 仍显示可用 / 在线。
- 渠道切换为钱包渠道时立即删除历史产品方 API Key、Secret Key 和本实例缓存。
- 公开目录的 `PullModels` 与一键同步都不给钱包渠道发送 `Authorization`。
- `0043_wallet_channels_drop_product_keys.sql` 删除所有钱包渠道历史上误存的 `channel:<key>` 与 `channel:<key>:secret` 凭证。
- 测试固定以下约束：
  - 钱包渠道设置产品方 Key 返回 400；
  - 切换到钱包渠道会清除历史 Key；
  - 钱包渠道拉取公开目录时 `Authorization` 必须为空。

## 5. 二次暴露

第一次修复删除了后台输入项和数据库凭证，但管理后台模型状态仍由 `ChannelHealthOf` / `ModelProblem` 计算。这两个函数继续把所有渠道都当成“必须有产品方 Key”，于是钱包模型被统一标成「不可用：渠道还没有设置 Key」。

这说明第一次修复只覆盖了表单、存储和目录请求，没有覆盖状态展示层。凭证规则已经改变，但所有读取 `SecretSet` 的判断没有一起审计。

对应修复：

- `CatalogChannel` 增加钱包渠道标记。
- 钱包渠道的健康状态只检查启停，不检查产品方 Key。
- 文本模型和 Agent 模型的状态计算都跳过钱包渠道的产品方 Key 检查。
- 新增跨层回归测试：钱包渠道 `secret_set=false` 时，渠道健康仍为可用，模型状态仍为在线。

## 6. 防止复发

TokenPay 钱包渠道的凭证规则只有一条：运行时只读 `wallet:<uid>`，后台不持有任何产品方 Key。模型目录按公开接口读取。

后续任何涉及钱包渠道的改动必须同时验证数据库凭证、后台表单、目录同步请求头、目录同步状态、渠道健康、模型状态和用户调用请求头。只修改文案或只删除表单都不算完成修复。
